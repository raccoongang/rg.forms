Incremental (per-field) server validation

Declarative validate_on — ADR-0004

Try it: type a username and click away (validate on blur) — admin, root, alice, bob are "taken". Then type a coupon (validate on change, debounced) — valid codes are SAVE10, WELCOME, RG2026.
Each field is checked by ordinary Django server-side validation returned over SSE. No per-field wiring in the view — just validate_on on the field and one reactive_validate endpoint.

{# validate_action points the generated per-field handlers at the SSE validation endpoint; action is the final (submit) URL. #} {% render_reactive_form form "Create account" action="" validate_action="/incremental-validation/validate/" %}

The form (Python)

class IncrementalValidationForm(ReactiveForm):
    username = ReactiveCharField(validate_on="blur")
    coupon = ReactiveCharField(required=False, validate_on="change", debounce=400)

    def clean_username(self):
        value = self.cleaned_data["username"].strip()
        if value.lower() in TAKEN_USERNAMES:
            raise ValidationError(f"'{value}' is already taken.")
        return value

The view (Python)

def validate(request):
    return reactive_validate(request, IncrementalValidationForm)
